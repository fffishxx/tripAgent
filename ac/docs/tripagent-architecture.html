Architecture · Agent 1004

TripAgent 整体结构

LangGraph 根图 + 出行规划子图；高德、滴滴 MCP、DeepSeek 作为外部能力；MySQL / PostgreSQL / Redis / Nacos / Langfuse 承载会话、状态与观测。

Request path

执行链路

  • 网关校验 JWT 后进入 /chat，由 TripAgent.execute 负责会话、停止标记与 Langfuse trace。
  • IntentNode 做结构化意图识别；TRAVEL_PLAN 进入出行子图，其余分流到路线、打车、知识/其他节点。
  • 子图输出行程后推送 1005，再用异步步行校验补发 1006；打车生成 1007 跳转订单。

SSE protocol

事件类型

  • 1001 文本增量：知识问答、路线/打车说明、追问。
  • 1005 首屏行程 JSON；1006 异步路线校验 warnings。
  • 1007 打车卡片（滴滴估价 / 跳转链接）；1002 结束，2001 错误。

Node contract

节点抽象 & 子图

  • 所有节点继承 BaseTripNode：execute()、route()、create_llm()、chat_llm()。
  • 出行子图：param_fill → planner ⇄ tools（最多 5 轮）→ format_plan；缺目的地进入 clarify。
  • 状态与会话由 Postgres Checkpointer 持久化；Redis 保存停止标记；Nacos 提供配置。
