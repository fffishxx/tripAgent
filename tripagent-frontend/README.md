# TripAgent Frontend

TripAgent 智能旅行助手前端。桌面端优先，采用蓝白色视觉风格。

**当前进度：阶段 7（整体联调与完善，已完成，暂未部署）**

## 技术栈

| 技术 | 用途 |
| --- | --- |
| Vue 3 + TypeScript | 前端框架 |
| Vite | 工程构建 |
| Pinia | 全局状态管理 |
| Vue Router | 页面路由 |
| Element Plus | 基础 UI 组件 |
| Axios | Java 后端请求 |
| Fetch + ReadableStream | Agent SSE 流式对话 |
| 高德 JS API + Web 服务 | 地图渲染、POI 搜索、路线规划 |
| Sass | 全局样式与设计变量 |

> 业务接口与 Agent 数据只经 Java 后端，不直接访问 Gateway 或 Python Agent。
> 阶段 4 的地图、POI 搜索和路线按确认的 `config` 方案直连高德，Key 通过前端环境配置注入。

## 前置服务

阶段 2 的真实登录与 AI 对话依赖以下服务：

| 服务 | 地址 | 说明 |
| --- | --- | --- |
| Java 后端 | `http://localhost:8080` | 登录注册、业务接口、Agent 代理 |
| Gateway | `http://localhost:10086` | Java 到 Python Agent 的内部转发 |
| Python Agent | `http://localhost:18089` | Agent 会话、SSE、历史会话 |

Python Agent 启动方式见 `../ac/README.md`，需要 Nacos、MySQL、PostgreSQL、Redis 等外部依赖可用。前端不保存任何服务 Token。

## 启动

前置要求：Node.js `^20.19.0 || >=22.12.0`（Vite 7 要求）。

```bash
cd tripagent-frontend
npm install
npm run dev
```

默认访问 `http://localhost:5173`。

其他命令：

```bash
npm run type-check   # TypeScript 类型检查
npm run build        # 类型检查 + 生产构建
npm run preview      # 预览构建产物
```

## 环境变量

开发环境读取 `.env.development`，生产构建读取 `.env.production`（也可在构建时通过同名环境变量注入）：

| 变量 | 默认值 | 说明 |
| --- | --- | --- |
| `VITE_API_BASE_URL` | `/api` | 浏览器请求前缀 |
| `VITE_PROXY_TARGET` | `http://localhost:8080` | Vite `/api` 代理目标 |
| `VITE_DEV_PORT` | `5173` | 开发端口 |
| `VITE_PREVIEW_PORT` | `4173` | `vite preview` 端口 |
| `VITE_AMAP_KEY` | 见本地 `.env.development` | 高德前端 Key |
| `VITE_AMAP_VERSION` | `2.0` | 高德 JS API 版本 |
| `VITE_AMAP_SECURITY_CODE` | 空 | Web端(JS API) Key 的安全密钥 |

### 高德地图 Key 与接入方式

阶段 4 使用 `config` 接入方式：

- JS API 负责地图底图、Marker、Polyline 等渲染；
- POI 搜索和路线规划通过高德 Web 服务 REST 完成；
- 收藏、加入行程仍调用 Java 接口。

当前配置的 Key 是**高德 Web 服务 Key**。高德 JS API 自带的 PlaceSearch/RouteSearch 对这类 Key 会返回 `USERKEY_PLAT_NOMATCH`，因此没有使用 JS API 内置搜索服务，而是通过 REST（已验证浏览器 CORS 可用）完成搜索和路线。

> 安全提示：Web 服务 Key 会随前端 bundle 暴露在浏览器中。当前实现是按已确认的 config 方案工作；正式上线建议更换为 Web端(JS API) Key + 安全密钥，或由后端代理高德 Web 服务。

后端未配置 CORS，开发环境通过 Vite 代理访问：

```text
浏览器 /api/**  →  Vite 5173  →  Java 8080 /api/**
```

生产环境需要反向代理 `/api` 到 Java 后端；SSE 路径必须关闭代理缓冲（例如 Nginx 需要关闭 `proxy_buffering`）。

## 阶段 2 已实现

### 登录与注册

- `/login` 对接 `POST /api/v1/auth/login`，保存后端返回的 USER_JWT（含过期时间）。
- `/register` 对接 `POST /api/v1/auth/register`，包含手机号、昵称（可选）、邮箱（可选）、密码与确认密码校验。
- 注册成功后回到登录页并回填手机号；注册失败会显示后端返回的具体错误（如手机号已注册）。
- 顶部用户区域展示真实昵称与脱敏手机号，支持退出登录。
- 路由守卫：
  - `我的行程 / 我的订单 / 个人中心 / 历史会话` 必须登录；
  - 新建对话、地图探索允许匿名访问；
  - 历史会话详情 `/chat/:sessionId` 必须登录；
  - 未登录访问受保护页面时携带 `redirect` 跳转登录，登录后回跳。
- Axios 自动携带 `Authorization: Bearer <USER_JWT>`。
- 统一处理 Java `Result`、Agent 原样 JSON 与 HTTP 错误；401 自动清理登录态并回到登录页。
- 阶段 1 的本地 mock 登录已移除，旧 mock 会话会自动失效。

### AI 对话（SSE）

- 登录用户进入新对话时调用 `POST /api/v1/agent/sessions` 创建会话并获取推荐问题。
- 匿名用户由前端生成 32 位 UUID 作为 `sessionId`，不创建会话元数据，也不提供历史。
- 通过 Fetch + ReadableStream 调用 `POST /api/v1/agent/chat`，逐帧解析原生 SSE。
- 已处理的事件：

| eventType | 前端处理 |
| --- | --- |
| `1001` | 追加文本增量，显示流式光标 |
| `1002` | 结束本轮 loading，关闭流 |
| `1005` | 渲染结构化行程卡片（每日安排、预算、住宿、美食） |
| `1006` | 渲染路线校验结果与提醒 |
| `1007` | 渲染打车车型选择/订单卡片 |
| `2001` | 展示本轮异常提示 |
| `2002` | 展示“需要登录”卡片，可跳转登录 |

- 支持停止生成：前端 AbortController 中止读取，并调用 `POST /api/v1/agent/sessions/stop` 停止服务端生成。
- 支持复制推荐问题并直接发送；支持 Enter 发送、Shift + Enter 换行、中文输入法组合输入保护。
- 行程卡片包含：目的地、天数、同行人群、预算、每日景点/时段/时长/推荐理由、住宿与美食建议。
- 路线提醒会展示具体路线和步行时间；打车卡片明确标记“模拟”，不会伪装成真实平台订单。
- 登录用户可通过 `/chat/:sessionId` 恢复历史会话消息、行程卡片和打车卡片。

### 历史会话

- 对接 `GET /api/v1/agent/sessions/history`，按接口返回的“当天 / 最近30天 / 最近1年 / 1年以上”分组展示。
- 支持按标题搜索、按时间组筛选、手动刷新。
- 点击会话进入 `/chat/:sessionId` 恢复详情。
- 支持修改标题（`PUT /api/v1/agent/sessions/history`）和删除会话（`DELETE`），删除后同步移除本地列表。
- 加载失败、空列表、无搜索结果都有独立状态。

### 统一视觉

- 蓝白色设计变量、Element Plus 主题覆盖、统一卡片/页头/空状态。
- 左侧固定导航 + 顶部用户区域，桌面优先，并适配平板与移动端底部导航。
- 山水素材暂用 CSS 渐变占位，集中在 `src/components/SceneryPlaceholder.vue`，后续可直接替换正式图片。

## 阶段 3 已实现：我的行程

### 行程列表

- 对接 `GET /api/v1/trips`，支持分页、标题/目的地关键词搜索和手动刷新。
- 每条行程显示目的地封面占位、标题、日期、天数、来源和最近更新时间。
- 状态按当前日期在本地推导为“待出行 / 进行中 / 已完成”，仅用于单条行程展示。
- 后端没有分类筛选和全量状态统计接口，因此**没有实现行程状态统计卡和状态筛选**，避免用分页数据拼出错误统计。
- 支持进入详情和创建新行程；空列表、无搜索结果、加载失败均有独立状态。

### 行程详情

- 对接 `GET /api/v1/trips/{tripId}`，按日期展示每天的主题、景点/安排、时段、停留时长、地址、安排理由和备注。
- 右侧展示来源、路线校验状态、创建/更新时间，以及预算、住宿、美食推荐和规划假设。
- “查看路线”抽屉按天展示站点、坐标和路线提醒；阶段 4 已接入高德真实地图与驾车路线。

### 手动创建

- 新增 `/trips/new` 创建页，支持标题、目的地、日期范围、描述。
- 日期范围变化会自动生成/重排对应天数；可使用日期选择器创建多日行程。
- 支持逐天添加景点/活动、填写地址、时段、停留时长、经纬度、理由和备注。
- 创建成功后进入行程详情；手动创建不调用 Agent。

### 手动编辑

- 支持统一保存和取消编辑。
- 可添加、删除景点，修改已有景点的名称、类型、日期归属、时段、时长、地址、理由、备注和坐标。
- 同一日期内支持拖拽排序，也支持拖到其他日期；同时提供上移/下移和“所属日期”选择作为非拖拽入口。
- 单日最多 20 个安排，行程至少保留 1 个安排。
- 编辑为本地草稿，点击保存时才通过 `PUT /api/v1/trips/{tripId}` 整单替换；保存期间不会调用 Agent。
- 编辑有未保存修改时，离开页面会二次确认；浏览器刷新/关闭会触发 `beforeunload` 提醒。
- 保存后清空旧路线校验结果，详情显示“未校验”，避免展示过期校验结论。

### 版本冲突与删除

- 保存时使用 `trip.version` 乐观锁；版本冲突返回 `40902` 时弹出冲突提示，并提供“加载最新行程”。
- 冲突后保存按钮暂停，加载最新行程会丢弃当前本地修改并退出编辑。
- 删除行程有二次确认；删除成功后回到列表并刷新。

## 阶段 4 已实现：地图探索

### 地图与搜索

- 通过前端配置加载高德 JS API 2.0，展示地图、自定义缩放/复位控件。
- 支持城市（可选）+ 关键词搜索，以及全部 / 景点 / 美食 / 酒店 / 购物 / 休闲分类筛选。
- POI 搜索通过高德 Web 服务 REST 完成，展示前 20 个结果和地图编号标记。
- 点击地图标记或结果列表会打开景点详情；优先展示高德 POI 图片，无图或图片加载失败时不展示备用图。
- 详情包含分类、评分、城市/区县、地址、电话等可用信息。

### 收藏

- 对接 Java 收藏接口：添加收藏、取消收藏、收藏列表。
- 收藏列表以 Drawer 展示，支持刷新和取消收藏；搜索结果与收藏状态按高德 POI ID 匹配，并带名称+坐标兜底。
- 地图浏览允许匿名；收藏、加入行程需要登录，未登录时弹出登录提示或显示登录入口。

### 加入已有行程

- 在景点详情点击“加入行程”，可选择任意已有行程与日期、时间段。
- 保存前重新读取最新行程和 `version`，通过 `PUT /api/v1/trips/{tripId}` 将 POI 作为新安排加入。
- 支持每日最多 20 个安排校验、版本冲突提示和空行程引导。
- 加入操作不调用 Agent，并清空旧路线校验结果。

### 路线规划

- 在景点详情中设置起点/终点，支持驾车/步行两种高德路线。
- 地图绘制真实路线折线、起终点标记，并展示距离与时长；支持清除路线。
- 阶段 3 的行程路线抽屉已升级：按天展示真实地图，并将连续站点按驾车分段规划后连成完整行程路线。

## 阶段 5 已实现：我的订单 / 模拟打车

### 订单列表

- 对接 `GET /api/v1/taxi/orders`，支持分页和状态筛选（全部 / 进行中 / 已完成 / 已取消）。
- 每行展示订单号、状态、起终点、城市、车型、距离/时长、模拟车费、来源和创建时间。
- 提供刷新、空状态、筛选无结果和加载失败状态。
- 页面持续展示“仅模拟订单、不接真实支付、不向真实平台派单、订单独立于行程”的提示。

### 订单详情

- 对接 `GET /api/v1/taxi/orders/{orderId}`，展示起终点、城市、距离、时长、车型、模拟车费和订单信息。
- 状态时间线展示创建、完成或取消及取消原因/时间。
- 已创建订单支持取消和模拟完成；已完成/已取消订单可再次发起模拟打车。
- 取消订单使用自定义确认弹窗，可填写最长 255 字的取消原因；模拟完成前有二次确认。
- 每次操作后按后端返回的最新订单刷新状态；订单状态冲突会重新拉取订单。

### 模拟打车创建流程

- 新增 `/orders/new` 创建页，通过高德地点建议选择上车点和目的地（获得经纬度）。
- 支持城市辅助搜索、交换起终点、地点搜索建议。
- 调用 `POST /api/v1/taxi/estimates` 获取模拟距离、时长和四种车型报价。
- 选择车型后调用 `POST /api/v1/taxi/orders`；Java 后端重新计算费用，前端不信任本地金额。
- 创建成功跳转订单详情；创建按钮有防重复提交处理。
- 全程不接入支付，也不写入我的行程。

## 阶段 6 已实现：个人中心

### 个人资料

- 对接 `GET /api/v1/users/me`，展示昵称、脱敏手机号、邮箱、用户 ID、账号状态、注册时间与最近登录时间。
- 资料卡同时展示行程、会话、订单、收藏四项统计；历史会话数依赖 Agent 服务，不可用时显示 `--`。
- 编辑弹窗对接 `PUT /api/v1/users/me`，支持修改昵称、邮箱和头像；昵称/邮箱有前端校验，手机号按接口约束只读。
- 头像通过 `POST /api/v1/uploads/avatar` 由 Java 服务端代理上传到 OSS，前端只发送文件和用户 JWT；上传成功后回填公开 URL，保存资料后生效。
- 保存成功后同步更新顶部用户区域与 Pinia/本地登录态，刷新页面仍显示最新资料。

### 旅行偏好

- 对接 `GET /api/v1/preferences`、`PUT /api/v1/preferences`。
- 支持出行人群、预算等级、交通方式、行程节奏四组枚举；兴趣与饮食偏好支持搜索、自由输入，最多 10 项；另有住宿偏好和补充说明。
- 前端校验标签长度、数量与补充说明 1000 字上限；保存时提交完整表单（后端为全量更新）。
- 偏好只来自个人中心的主动设置，不从聊天内容自动提取；Agent 规划时由后端读取。

### 账户安全与退出

- 展示登录手机号、修改密码、更换手机号等账户安全入口；当前后端未提供改密/换绑接口，入口以“暂未开放”说明。
- 退出登录使用统一确认弹窗，清除本地 JWT 与用户缓存后回到聊天首页；接口文档说明无服务端登出接口。

## 阶段 7 已实现：整体联调与完善

### 鉴权、SSE 与全局异常

- Axios、SSE、头像上传统一处理 HTTP 401 / 业务码 40101：清除本地登录态并跳转登录页，保留 `redirect`。
- SSE 增加 Content-Type 校验，非事件流响应按错误处理；识别 `1002/2001/2002` 与 `[DONE]` 终止标记。
- 服务端未发送结束标记就关流、读取异常、网络错误时提示“回复生成中断”，保留已接收内容、恢复输入框并复位发送状态。
- 增加 90 秒流空闲超时；用户主动停止、停止中的重复点击、组件卸载均有保护。
- 登录用户创建会话后把会话 ID 同步到 `/chat/:sessionId`，刷新可恢复当前会话；侧边栏“新建对话”在已处于聊天页时也能创建新会话。
- 全局 `app.config.errorHandler`、`router.onError`、`unhandledrejection` 统一提示异常（3 秒内去重）。
- 头像上传增加 15 秒超时；localStorage 读写失败时降级为内存态登录，不阻塞页面。

### 空态、失败态与重试

- 行程/订单/历史列表保留骨架屏、空态、搜索无结果、失败重试；快速切换筛选或翻页时用请求序号避免旧响应覆盖新结果。
- 列表页码超过最后一页时自动回退；历史列表、行程列表、订单列表的搜索词/筛选/页码写入 URL query，刷新或返回时恢复。
- 个人中心资料、统计、偏好分别提供加载态、失败提示与重试；统计部分失败不影响资料和偏好。
- 地图、路线、打车地点搜索、行程路线抽屉等失败场景提供错误说明与重试入口。

### 表单、离开与版本冲突

- 景点编辑弹窗增加提交锁，避免快速双击重复添加；已满 20 项的日期禁用并在提交时再次校验。
- 创建行程、编辑行程、模拟打车、资料弹窗、旅行偏好增加未保存离开/关闭确认；保存或创建中禁止离开，组件卸载后不再执行成功跳转。
- 行程版本冲突继续使用 `version` 乐观锁；冲突后“加载最新行程”增加二次确认，加载失败不再误报成功。
- 打车估价返回空车型时展示“暂无可用车型 + 重新估价”。

### 地图异常

- 高德 JS 脚本加载失败/超时会移除残留 script；地图初始化增加防重锁，重试前销毁旧实例。
- Key 缺失时隐藏无效的“重新加载地图”按钮并提示配置方式。
- 地图路线规划失败可重试；打车地点建议失败不再静默。

### 状态恢复范围

- 已恢复：登录态、历史会话、当前聊天会话、列表筛选与页码。
- 未做持久化（按阶段 7 确认的范围）：行程创建/编辑草稿、地图搜索状态、打车表单、资料与偏好弹窗内未保存内容；这些场景提供离开确认，但不跨刷新恢复。

## 接口对接约定

- 前端业务 API 前缀：`/api/v1/**`，使用用户 JWT，字段为 camelCase。
- Java 业务接口响应为 `{ code, message, data, requestId, timestamp }`。
- Agent 会话/历史接口原样透传 Python JSON，不套 `Result`。
- SSE 返回原生 `text/event-stream`，不使用 `Result`。
- 前端不保存、不接触 `SERVICE_TOKEN`、`X-User-Id`、`X-Service-Token` 等服务端字段。
- 高德地图/POI/路线按阶段 4 确认的 config 方案直连高德 REST；收藏与行程修改仍走 Java。
- 具体字段以 `../docs/project/API_DESIGN.md` 和 `../docs/project/PROJECT_OVERVIEW.md` 为准。

## 已知遗留与说明

- 阶段 7 按设计暂不部署：未提供前端 Dockerfile/Nginx/SPA 回退/`/api` 反向代理配置，后续部署阶段再补。
- 阶段 7 只实现标准状态恢复：行程/打车草稿、地图搜索、资料偏好弹窗内修改不跨刷新持久化，但都有离开确认。
- 匿名聊天会话不落库，刷新后无法恢复；登录用户创建会话后可通过 `/chat/:sessionId` 恢复。
- SSE 目前没有断线重连或断点续传，异常后只能重新发送；空闲超时为固定 90 秒。
- 行程版本冲突确认加载最新后，本地未保存修改会丢弃（界面明确提示），未实现本地编辑合并。
- 后端直连创建行程/订单接口已支持可选 `Idempotency-Key` 并返回 `idempotentReplay`；前端 API 封装已支持传入该 Header，当前页面仍以按钮锁与禁止重复提交为主，尚未为每次提交自动生成稳定幂等键。
- 个人中心的“历史会话”统计依赖 Python Agent / Gateway；Agent 不可用时该卡显示 `--`，其余资料与偏好功能不受影响。
- 头像上传依赖 Java 后端 OSS 配置（`OSS_ENDPOINT`、`OSS_BUCKET`、`OSS_ACCESS_KEY_ID`、`OSS_ACCESS_KEY_SECRET`）；未配置时页面明确提示上传服务未配置。
- 后端未提供修改密码、手机号换绑和头像/OSS 删除接口；更换头像后旧对象不会自动清理。
- 后端无服务端登出接口，前端仅清除本地 JWT。
- 打车创建流程的地点上选择依赖高德地图 Key；无 Key 时只能查看已有订单，无法搜索新地点。
- 后端没有删除订单接口，订单只能“取消”或“模拟完成”；阶段 5 联调新增的模拟订单会保留在测试账号中。
- 订单状态 `CREATED` 在前端显示为“进行中”，与后端 `statusText=已创建` 语义一致，便于列表筛选。
- 当前高德接入使用 Web 服务 Key 的 config 方式；Key 会暴露在前端。正式上线建议换成 Web端(JS API) Key + 安全密钥，或使用后端代理。
- 高德 POI 搜索最多展示前 20 个结果，没有继续滚动加载更多。
- 分类筛选使用高德类型码，结果可能包含相近类型地点。
- 后端没有行程分类筛选和全量统计接口，阶段 3 未实现状态统计卡和筛选；只展示单条行程的日期推导状态与分页总数。
- 行程详情编辑只修改每日安排，标题、目的地和日期在已有行程中保持只读；这些信息可在创建新行程时填写。
- Element Plus 当前全量引入，主包体积较大；后续可切换按需自动引入。
- 山水插画、正式图标等视觉素材待提供后替换占位。
